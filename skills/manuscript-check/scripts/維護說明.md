# 編輯工具包：執行與維護說明

> 給維護者與 AI 助理看的說明。使用者操作方式見 `使用說明.md`。

這是一組**規則式的編輯檢查工具**（Python 程式）。工具本身不使用 AI：每一筆結果都來自寫死的規則或詞表，同樣的輸入永遠得到同樣的輸出。

## 一、工具一覽

| 工具 | 用途 | 輸入 | 產出（預設存在輸入檔旁邊） |
|---|---|---|---|
| `稿件健檢.py` | Word 整稿階段的檢查：標點、簡體與異常字元、罕用字、同書異形詞、章節與圖表編號、字數與長句、外文拼寫、參考文獻 | 一個或多個 `.docx` | `稿件名_健檢報表_日期-時間.xlsx` |
| `排版比對.py` | 定稿 Word 檔與排版 PDF 逐字比對，找漏排、錯字、多字、整段漏排 | 一個 `.docx`＋一個 `.pdf` | `定稿名_排版比對_日期-時間.xlsx` |
| `索引頁碼.py` | 依索引詞表在排版 PDF 找出每個詞的書頁，排成索引 | 索引詞表（`.txt`／`.csv`／`.xlsx`）＋一個 `.pdf` | `PDF名_索引_日期-時間.docx`＋`PDF名_索引核對_日期-時間.xlsx` |

各項檢查的細節、報表怎麼看、已知限制，見 `使用說明.md`。

## 二、怎麼執行

### Python
需要能執行 `import docx, openpyxl, pdfplumber` 的 Python 3（套件見 `requirements.txt`）。先用 `-c "import docx, openpyxl, pdfplumber"` 確認，通過才用。Windows 上 `python`／`python3` 可能只是 WindowsApps 空殼（執行了沒有任何輸出），所以一定要用 import 測試確認，不要只看指令存不存在。

`pip install -r requirements.txt` 會從網路下載套件，AI 助理代跑時須先問使用者。

### 指令（在本資料夾內執行；路徑有空格或中文時加引號）
```
<python> 稿件健檢.py 書稿.docx [書稿2.docx ...] [--只跑 標點 簡體 罕用字 異形 結構 統計 外文 文獻] [--輸出 資料夾]
<python> 排版比對.py 定稿.docx 排版稿.pdf [--輸出 資料夾]
<python> 索引頁碼.py 索引詞表.txt 排版稿.pdf [--輸出 資料夾]
```
- 所有工具都另有 `--設定 路徑` 參數；預設是 `設定/設定.ini`。
- 報表預設寫在輸入檔旁邊（`索引頁碼.py` 例外：寫在**索引詞表**旁邊，檔名卻取自 PDF）。**工具不會自建輸出資料夾**，用 `--輸出` 時先建好再跑。
- Windows 使用者也可以把檔案拖到對應的 `.bat`（`健檢.bat`→`稿件健檢.py`、`排版比對.bat`、`索引頁碼.bat`）。`.bat` 找 Python 的順序是 `PYTHON_EXE`→`py -3`→`python`，每一個都用 import 測試確認套件齊全才採用。

### 環境檢查（換電腦或改程式前後）
```
<python> tests/test_all.py
<python> tests/test_collate.py
<python> tests/test_index.py
```
三支都印出 `ALL PASS` 才能用（Windows 可雙擊 `環境檢查.bat`）。測試失敗時回報失敗項目名稱，不要改程式讓它通過。

## 三、「AI 不參與」的稿件

部分書稿依出版社或作者要求，編輯工作不允許 AI 參與。**哪一份稿件屬於這種，由使用者指定**；使用者沒說，就照一般稿務處理。

使用者指定某份稿件「AI 不參與」時，AI 助理對**那份稿件**只代跑工具、轉述終端機印出的摘要與報表路徑，不讀稿件、不開報表、不做編輯判斷。要 AI 解讀報表或提出修改建議時，先提醒這會讓 AI 參與這份稿件，確認後才做；確認只及於那一次請求。

**範圍比「不使用工具」窄**：工具本身是規則式、本機執行，屬「程式輔助」，所以在這類稿件上仍可代為執行。

## 四、設定檔（`設定/`）

使用者要調整工具行為時，改的是設定檔，不是程式。改之前先說明會改哪一項、改成什麼。

| 檔案 | 內容 |
|---|---|
| `設定.ini` | 各項門檻與選項，每一項上方都有中文註解（本檔以 `;` 為註解） |
| `詞表_詞換詞.txt` | 同書異形詞檢查用的詞表（格式：`原字,改字,模式,例外`）。內附入門小表，建議換成自己的用字體例 |
| `疊字白名單.txt` | 合法的疊字與跨詞界的排除語境 |
| `一簡多繁.txt`、`錯轉.txt` | 簡體殘留與錯轉繁的檢查清單（與 `zh-tw-guard` skill 共用同一份判準） |
| `台灣正字.txt` | 標準 Big5 沒收、但台灣正式使用的字（酶、肽……），簡體檢查不報；罕用字清單照列（與 `zh-tw-guard` 共用） |
| `譯名表.txt` | 標準譯名與變體 |
| `索引詞表範本.txt` | 索引詞表的格式範本 |

清單都是 **UTF-8** 文字檔，以 `'` 開頭的行是註解。Windows PowerShell 5.1 寫檔預設不是 UTF-8，改清單時用編輯器或顯式指定 `-Encoding utf8`。

## 五、維護與優化

### 不能改變的底線
1. **工具必須維持規則式**：不得在工具裡呼叫任何 AI 或雲端服務（大型語言模型 API、線上翻譯、線上查詢）。工具在本機執行、結果可以重現，是「程式輔助」能成立的前提——也是第三節「AI 不參與」的稿件還能代跑工具的理由。
2. **工具只讀稿件**：不得寫入、覆蓋或移動使用者的稿件與 PDF；產出一律另存新檔。

### 改動的流程
1. **改之前**：先跑第二節的三支測試，確認目前全部 `ALL PASS`，當作比較基準。
2. **修錯誤或新增功能**：先在 `tests/` 加一個會失敗的測試案例，確認它真的會失敗，再改程式讓它通過。
3. **改之後**：全部測試 `ALL PASS` 才算完成。不要為了讓測試通過而放寬或刪除預期結果；確實要改預期，說明理由。
4. **留紀錄**：在 `變更紀錄.md` 最後追加一筆，寫日期、改了什麼、為什麼改、怎麼驗證。只追加，不刪改舊的。
5. **說明文件同步**：改到使用方式、設定項目或限制時，同步更新 `使用說明.md` 和本檔。

### 設定與程式的分工
- 使用者要調整參數（門檻、詞表、白名單）時，改 `設定/` 就好，不要改程式。
- 同一種誤報反覆出現時，優先加白名單或排除詞，其次才改判斷規則。

## 六、常見狀況

| 狀況 | 處理 |
|---|---|
| 稿件是 `.doc` | 請使用者在 Word 另存為 `.docx` |
| 「PDF 沒有文字層」 | 掃描檔無法處理；請使用者向排版方要排版軟體直接輸出的 PDF |
| 排版比對的總覽寫「全形標點錯接⋯明顯偏高」 | PDF 文字抽取的行序可能錯亂，先對照 PDF 抽看幾筆差異再判讀 |
| 排版比對出現大量「文字不同」 | 先確認定稿和排版稿是不是同一個版本 |
| 索引的書頁不對 | 在 `設定.ini` 的 `[索引]` 填 `頁碼差`（PDF 頁減書頁），或用 `掃描範圍` 略過前頁 |
