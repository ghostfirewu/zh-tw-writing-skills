# 繁中 AI 腔過濾

## 核心判準（每一句都先過這關）

AI 味的根源是**平庸，不是錯誤**：文法全對，卻靠灌水詞、缺具體細節、以及「換任何同類主題都成立」的假融貫充版面。

> **刪掉這句，讀者少知道哪個具體事實、立場或情緒？沒少＝該刪。**

例：「這款工具無疑為創作者帶來了全新的契機」→ 刪掉後讀者什麼都沒少，刪。「這款工具把排程從五步縮成一步」→ 刪掉讀者就不知道省了什麼，留。

**改寫不加料**：把空話換成具體事實時，**只能用原文或上下文已有的事實**。原文沒有，就刪掉，不替作者編數字、案例或引語。例：原文「大幅提升效率」而全文沒有數字 → 改「提升效率」或刪，**不得**寫成「效率提升 40%」。改寫的完整紀律見 `references/rewrite-safety.md`。

## 何時用、用多重

| 情境 | 處置 |
|---|---|
| 自己寫的對外文字（貼文、文案、文章、信件） | 寫完照本清單自查，直接改 |
| 使用者給的稿子，要求「去 AI 味」 | 照下方流程改，附判斷台帳 |
| 書稿、譯稿（作者的作品） | **只標注、不逕改**：列出位置與建議改法，由作者決定 |
| 內部紀錄（筆記、commit message、會議記錄） | 不必套用 |

拿不準算不算對外：看「這段文字本身會不會被第三方讀到」。

## 流程（改別人的稿子時）

**修正順序由深到淺**：先看立場與主詞，再看結構，最後才看用詞和符號。只換掉灌水詞、不處理結構，AI 腔還是在。

1. **先分配，再動手**：列出各段或各小節，每一列標「保留」或「修改」，**預設保留**。只改真的有問題的地方（`references/rewrite-safety.md` 第 4 節）。
2. **機械掃描**（有檔案時）：
   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/skills/zh-tw-anti-slop/scripts/slop_scan.py 文案.md
   ```
   沒有 `${CLAUDE_PLUGIN_ROOT}` 的環境，改用本 skill 資料夾下的 `scripts/slop_scan.py`。也可以用 `-` 從標準輸入讀。
   - 掃描器只找**候選**。術語（心理學書稿的「療癒」）、字面義（「落地窗」「指紋解鎖」）、提及而非使用（「我戒掉了『賦能』」）都不改。判準：換成建議的替代詞後意思變了或變怪，就是字面義。
   - 它也會抓 Markdown 粗體失效（`**` 貼著中文標點時會原樣顯示）。
   - 沒命中不等於沒問題。
3. **通讀判斷**：掃描器抓不到的要自己讀。
   - 由深到淺：擬人（物件當主詞）、二元對比是否在糾正真實誤解、骨架三點強迫症、強制昇華結尾。
   - 接著看：三項排比湊整、同義詞刻意輪替、極短句戲劇轟炸、格言公式。
   - 判準見 `references/rules.md`（高頻禁用詞與句型）、`references/patterns.md`（翻譯腔、AI 慣性、擬人、版面）。
4. **逐筆記判斷台帳**：每筆命中寫「改了」或「保留，理由是…」，保留一定要附理由的種類（格式見 `references/rewrite-safety.md` 第 5 節）。
5. **改寫**：守住語意四點（主張、比重、強度、句子的功能），強度兩個方向都不能動，改出來的詞要查得到。
6. **改寫前後比對**：
   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/skills/zh-tw-anti-slop/scripts/rewrite_diff.py 原文.md 改寫後.md
   ```
   會列出數字、英文詞、引語的增減，以及保證、推測、範圍限定等語氣用語的變化。只要有任何一筆增減，結束代碼就是 1；標 ⚠️ 的是最可能改高強度的幾筆，但沒標的也要看。每一筆都回頭對原文判斷：是加料或改了強度，就退回原文措辭；是照規則刻意刪的（刪墊片詞讓「評價」變少、刪轉場詞讓「因果」變少、二元對比改直述讓「但」變少），確認後放行。
7. **雙向自審**：改過頭？對照 `references/protect.md` 還原誤改；改不夠？對照 `rules.md`、`patterns.md` 補漏。再統計每一類修正套了幾處，同一種改法套滿全篇就退回幾處。
8. **用語**：繁中稿同時跑 `zh-tw-guard`（中國用語、簡體殘留）。

**變形**：
- 自己寫的文字：沒有原文可比，只做第 2、3、7、8 步（掃描、通讀、雙向自審、用語），寫完直接改。
- 書稿、譯稿（只標注不逕改）：第 5 步的紀律套用在你寫的建議改法上（建議改法本身也不能加料、改強度）；第 6 步拿原文和「套用全部建議後的版本」比對，或在回報中註明未比對。

## 最常見的十種（完整清單見 `references/rules.md`）

| 型 | 例 | 改法 |
|---|---|---|
| 灌水動詞 | 賦能、助力、打造、落地 | 換成具體動作（讓…能夠、做出、上線） |
| 墊片詞 | 值得注意的是、說到底、本質上 | 刪掉讓主語直接發力；它若真在下評價，把評價移到句子後半 |
| 二元對比 | X 不僅僅是 Y，它更是 Z | 拿掉否定主張不變就直接陳述 Z；在糾正真實誤解就保留 |
| 擬人 | 數據告訴我們、AI 正在重新定義寫作 | 換回真正的主詞（從數據看得出…；寫作者開始用 AI…） |
| 開場白套路 | 在現今瞬息萬變的數位時代中 | 刪，從主句開始 |
| 翻譯腔 | 進行調查、在…的過程中、是一個值得…的 | 調查、…時、這個…值得 |
| 模糊關聯 | 息息相關、相輔相成 | 寫出誰影響誰，寫不出就刪 |
| 模糊歸因 | 研究顯示、業界普遍認為（沒有出處） | 別人的文字：標「請補出處」，不代填、不逕刪；自己的產出：查得到就補出處，查不到就刪或改寫 |
| 強制昇華結尾 | 儘管仍面臨挑戰，但前景可期 | 停在最後一個事實；不改寫成另一句金句 |
| 聊天殘渣 | 希望有幫助、好問題！、作為 AI | 全刪（書稿例外：只標注） |

## 回報格式（改別人的稿時）

1. 改寫後的本文（書稿則是附標注的原文）。
2. 判斷台帳：逐筆列「改了／保留＋理由」。
3. 改寫前後比對的結果，以及你對每一筆的處理。
4. 統計：共改幾處、各型幾處；有沒有同一種改法套滿全篇。
