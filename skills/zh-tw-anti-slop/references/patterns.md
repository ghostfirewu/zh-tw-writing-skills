# AI 痕跡判準細表

> `rules.md` 收的是高頻禁用詞與句型；本檔是細項擴充，按「症狀從哪裡來」分四張表：
> - **翻譯腔**：英文句法的直譯殘留。
> - **AI 慣性**：AI 為了顯得完整、深刻而**加上去**的贅生物。
> - **擬人**：讓物件、概念做人的動作。
> - **版面與格式**：排版層的痕跡。
>
> **處置看文字是誰的**：
> - 自己的產出、社群文案：照修法欄直接改。
> - 書稿、譯稿（作者的作品）：一律只標注、附建議改法，由作者決定。
> - **例外**：「模糊歸因」在別人的文字裡一律只標注、不代填、不逕刪；自己的產出則查到出處就補上，查不到就刪掉或改寫成不需要出處的說法，不在成品裡留下「請補出處」。
>
> 本檔命中的詞句若在 `rules.md` 已有，替代方向以 `rules.md` 為準。改寫時一律遵守 `rewrite-safety.md`。

## 1. 翻譯腔

| 問題 | 判準 | 修法（例） |
|---|---|---|
| 冗餘量詞 | 「一個／一種／一位／一項」多為英文 a/an 的直譯。**刪除測試**：整個量詞短語刪掉後句子仍通、語意不變 → 刪 | ❌「這是一個值得深思的問題」→ ✅「這個問題值得深思」。**不觸發**：量詞承載真實計數（「只有一種解法」）|
| 框式介詞 | 「在……的過程中／在……方面／在……上／對……而言／……的情況下」是英文介詞框直譯。拆框留核心 | ❌「在學習對位法的過程中，學生常在節奏方面遇到困難」→ ✅「學習對位法時，學生常卡在節奏」。**不觸發**：框內短語過長，拆了會斷句 |
| 英式句框 | ①「最……之一」（one of the most）；②「當……的時候」（when）開句；③列舉最後一項前硬塞「和／以及」；④一句裡堆三個以上結構性「的」| ①改寫時強度不得變，找不到等強度說法就保留；②❌「當我們分析資料的時候」→ ✅「分析資料時」；③❌「春、夏、秋和冬」→ ✅「春夏秋冬」；④❌「公司的核心的價值的展現」→ ✅「公司核心價值的展現」。**不觸發**：「之一」承載真實排名範圍（「全台三大港之一」）；「當」字句與主句形成對照（「當別人還在觀望，他已經下單」）|
| 自問自答 | 「這意味著什麼？」「為什麼會這樣？」——一章（或一篇）至多一次，且答案不是理所當然。要看全章才判得了，分段處理時留到最後統一掃 | 超額或答案理所當然 → 刪問句，答案併入正文 |

## 2. AI 慣性

> 「強制昇華結尾」「骨架三點強迫症」「轉場詞通膨」「文風斷層」要看全章才判得了，分段處理時留到合稿後再掃。

| 問題 | 判準 | 修法（例） |
|---|---|---|
| 句尾綴掛評論 | 逗號後的分句不帶新事實，只回頭對前句下評價（常是英文 -ing 尾巴的直譯，但中文原創稿同樣會有）| ❌「他把配方改了三次，凸顯了品管的重要性」→ ✅「他把配方改了三次」。**不觸發**：尾巴帶新事實（「……，良率從六成升到九成」）|
| 意義膨脹 | 把可查證的具體事實換成不可查證的抽象讚辭。**通用性測試**：主詞換成任何同類對象，這句照樣成立 → 命中 | ❌「成為社區凝聚的象徵」「為產業點亮一盞明燈」→ 還原成原文已有的事實（「開幕後三個月，週末平均來 400 人」）；原文沒有事實就刪，不代補。**不觸發**：作者明確表態的評價句（「我認為這是他最好的作品」）|
| 強制昇華結尾 | 結尾段沒有新事實、沒有具體行動，只重述前文再抬升：「儘管仍面臨挑戰，但……值得期待」「展望未來……」「相信在各方努力下，……必將走得更遠」| 停在最後一個事實或主張。**結尾金句只刪、不改寫成另一句更漂亮的金句**（那只是換一句同型的昇華）。**不觸發**：有具體內容的行動建議、預測、結論 |
| 模糊歸因（假共識）| 「業界普遍認為」「有專家指出」「研究顯示」「許多人認為」而全文沒有出處，或把一兩個來源說成廣泛共識。**反方向同列——假精確**：沒有出處卻精確到小數點的數字（「效率提升 42%」「73.6% 的使用者」）| 別人的文字：一律標「請補出處」，**不代填、不逕刪、不改寫成概略說法**——刪掉等於替作者背書，填進去就是捏造。自己的產出照檔頭例外處理。**不觸發**：緊鄰處已有註腳、書目、受訪者姓名。掃描器只認得三種出處格式（前面的「某年調查」、後面括號裡的年份、`[^1]` 或上標註腳），其他格式的出處要自己看 |
| 抽象名詞化 | 「的＋抽象名詞」把動作包成名詞，或「-性／-化／-感」堆疊：「……的建構／的實現／的提升／的深化／的探索」| ❌「自我的探索」「認同感的建構」→ ✅「找自己」「知道自己是誰」。改寫只到還原動詞為止，改完照 `rewrite-safety.md` 第 3 節查生造詞。**不觸發**：既有學術術語（資訊不對稱、認知失調）、作者自創術語 |
| 骨架三點強迫症 | 章節骨架硬拆三份：三點之間沒有邏輯交集，或只是把一句話切三段（「三大優勢」「主要體現在以下三個面向」）| 併回連續段落。分工：`rules.md` 的「三項排比湊整」管一句話裡的三個形容詞，版面層的「條列碎片化」管一段話被編號，本列管整個章節。**不觸發**：真有三個獨立並列項、各帶不同事實 |
| 具體錨點虛化 | 正文出現「某位／某家／某個午後／近年來／不久前／有一次」等虛指 | 標「建議補具體時間、地點、人名」，**不代填**。**不觸發**：作者刻意匿名以保護當事人；譯稿原文即虛指；修辭性泛稱（「有些人會說……」）|
| 促銷腔形容詞通膨 | 形容詞不帶可查證事實，換掉主詞照樣成立；動詞用「擁有／坐擁／設有／匯聚」取代單純的「有」| ❌「坐落於城市的心臟地帶」「享譽盛名」→ 改列原文已有的具體內容（「離捷運站 200 公尺」）。**不觸發**：品牌、產品名稱本體（但形容它的空洞形容詞仍算）|
| 轉場詞通膨 | 段段以轉場詞開頭，或同一轉場詞一章超過 3 次：「此外」「再者」「與此同時」「另一方面」「更重要的是」| 依實際邏輯關係改寫，或直接刪。**不觸發**：全章 3 次以內，且各處確有遞進或轉折 |
| 文風斷層 | 同一篇內風格突然換手：前幾段句長參差、有具體地名與自嘲，中段句長整齊、形容詞變多，之後又變回來（常見於頭尾作者寫、中段交給 AI 補）。只看同篇內的相對落差 | 標出「第 X–Y 段與前後文風不同」並寫出徵兆。斷層段照本檔處理，其餘段照 `protect.md` 手下留情，**不把全篇拉成同一語氣**。**不觸發**：體例本來就換聲部（引文、訪談、附錄、案例框）|

## 3. 擬人：物件當主詞做人的動作

AI 常讓數據、技術、概念「告訴」「選擇」「希望」，這是英文無生物主語的直譯。

**兩步判準**：
1. **讀者會不會照字面想像那個動作？** 第一次看到這個述語的人會不會想像物件真的在說話、在選擇？會 → 疑似擬人。
2. **試著換回具體的人或事物當主詞**。換得出來就照換；換不出來，代表這句其實沒說清楚在講什麼，刪掉或先把內容想清楚再寫。

| ❌ | ✅ |
|---|---|
| 數據告訴我們，使用者偏好深色模式 | 從數據看得出使用者偏好深色模式 |
| AI 正在重新定義寫作 | 寫作者開始用 AI 打草稿、查資料（寫出誰做了什麼）|
| 這套系統希望使用者多留一點時間 | 設計者希望使用者多留一點時間 |
| 這個問題仍然是開放的 | 這個問題還沒有答案 |

**不觸發**：
- 客觀描述工具的功能：「這個工具會收集日誌」「系統每小時備份一次」。
- 中文早已通用的說法：「數據顯示」「研究指出」（是否缺出處另照模糊歸因判）、「市場用腳投票」。判斷方法：AI 普及以前的人類文章裡也常見，就保留。

## 4. 版面與格式

| 問題 | 判準 | 修法 |
|---|---|---|
| 中文混半形標點 | 中文段落出現 `,` `.` `:` | 改全形「，。：」；數字、單位、網址、程式碼維持半形 |
| 破折號濫用 | 頻率高於每 300–500 字一次（破折號本身是台灣標準標點，問題在太密）| 多數改逗號或句號；保留的用全形 —— |
| 粗體轟炸 | 一段多處加粗 | 一段最多 2–3 個詞加粗 |
| 粗體失效 | Markdown 的 `**` 緊貼中文標點又緊貼文字時不會生效，`**` 原樣顯示：`接著**「設定」**再` | 依序試：①只包括號內側（`接著「**設定**」再`）；②句末標點移到 `**` 外（`**必須。**詳見` → `**必須**。詳見`）；③都不行時，在 `**` 的**外側**加一個半形空格（`接著 **「設定」** 再`），加在內側反而會失效。`slop_scan.py` 會自動抓貼著中文的情況（純英數旁的 `**` 多半是程式碼，不報）|
| 內嵌粗體標題列 | `**詞**：定義句` 連續堆疊 | 改成正常句子敘述 |
| emoji 堆疊 | 一則貼文多個 emoji 連堆（💡✅🔥🔥）| 刪到 0–1 個，用文字承載語氣 |
| 條列碎片化 | 「首先／其次／最後」硬三等分、把一句話拆成編號 | 併回段落，只在真有並列時列點 |
| 表格濫用 | 一句話的內容硬做成表、空洞的「優點／缺點」表 | 改回敘述；真正多維比較才用表 |
| 句長齊一 | 連續三句長度、結構幾乎一樣 | 打斷一句改短，或併成長句 |
| 純文字平台誤用 Markdown | FB／IG／LINE 貼文出現 `**粗體**`、`# 標題`、`- 列表` | 這些平台不吃 Markdown，符號會原樣顯示；改用換行、引號「」、短句 |
| 引號濫用 | 引號只有四種正當用途：提及某詞、術語首次出現、直接引文、篇章名。其餘過刪除測試（拿掉後語意不變也沒有歧義就拿掉）| 刪多餘引號；「所謂『賦能』」這種雙重標記擇一。**不觸發**：引述原話 |
| 括號補充濫用 | 一段裡兩處以上（像這樣塞一句說明）的括號插話，補的是次要解釋 | 重要的寫進正文，不重要的刪。**不觸發**：外文原名、縮寫全稱、年份、出處這類標注型括號；作者刻意的自我修正插話 |
| 段尾微型總結 | 每段結尾都收「因此……」「這說明……」，或兩段以上用同句式收尾 | 刪；全文只在真正結尾總結一次，或不總結 |
| 小標題濫設 | 千字內短文設小標題，把短文再切碎 | 刪小標題，靠段落推進。**書稿只標注，不刪標題** |
| AI 工具標記殘留 | 正文夾雜生成工具的內部代碼：`oaicite`、`contentReference`、`turn0search0`、`[cite: 1]`、`[span_1]`、`ppl-ai-file-upload`。**這是原則不是清單**：代碼會隨版本變，看不出語意、疑似機器插入的都算 | 保留內容本體、清掉標記。網址參數（`utm_source=chatgpt.com`）另見 `rules.md` 四。**不觸發**：正文在**討論**這些代碼本身；程式碼區塊 |
