# 繁中守門（zh-TW）

AI 寫繁中最常漏的四類問題，由準到寬：

| 類別 | 例 | 處置 |
|---|---|---|
| **簡體字** | 这、个、东 | 一律改正體（地名、日本人名、引用原文可能是刻意保留，先確認） |
| **一簡多繁** | 以后、這里、干淨 | 簡體形本身也是正體字，轉換器常漏轉。改正（皇后、公里、若干這類排除詞不報） |
| **錯轉繁** | 頭發、關系、皇後 | 轉換器選錯對應字。改正；跨詞界時是誤報（頭＋發燙） |
| **中國用語** | 視頻、軟件、信息 | A 級直接換；**B 級看語境**，見下 |

## 中國用語的兩級

- **A 級（安全直換）**：視頻→影片、軟件→軟體、信息→資訊、服務器→伺服器…沒有撞詞風險，直接換。
- **B 級（看語境）**：同一個詞在台灣也有正常用法，只在「替換語境」改。例：
  - 程序：「這個程序跑不動」→程式；「申請程序很繁瑣」**保留**（步驟義是台灣通用說法）。
  - 質量：「產品質量」→品質；「質量守恆」**保留**（物理 mass）。
  - 支持：「支持 PDF 格式」→支援；「我支持你」**保留**。

**含短詞的複合詞先比長詞**：音視頻→影音（不是「音影片」）、程序員→程式設計師（不是「程式員」）。

完整對照表與每個 B 級詞的保留語境：`references/terms.md`。一簡多繁、錯轉命中後該改成哪個正體：`references/char-variants.md`。

## 流程

1. **自己寫繁中時**：寫完自查上表四類。長文、技術文、引用了簡體來源（網頁、搜尋結果）改寫的段落最容易漏，這幾種一定要查。
2. **檢查檔案時**跑掃描器：
   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/skills/zh-tw-guard/scripts/zhtw_check.py 文章.md
   ```
   沒有 `${CLAUDE_PLUGIN_ROOT}` 的環境，改用本 skill 資料夾下的 `scripts/zhtw_check.py`。只用 Python 標準函式庫，不必安裝套件。
   - `--level A`：只報安全直換的用語（大量稿件先清這層）。
   - `--only 簡體,一簡多繁,錯轉`：只查字形，不查用語（類別用逗號分隔，可放在檔名前或後）。
   - `--json`：給程式讀。`-`：從標準輸入讀。
   - 結束代碼：有簡體／一簡多繁／錯轉／A 級命中＝1，可接 CI。
   - Markdown 的程式碼區塊不查用語（變數名、字串常值常是刻意的），仍查簡體字。
3. **逐筆判斷**：B 級命中照 `references/terms.md` 的保留語境判；簡體字命中先確認是不是刻意保留的專名或引文。
4. **改稿**：
   - 自己的產出：直接改。
   - 別人的稿子：A 級與字形錯誤可直接改（說明改了幾處）；B 級列出建議，讓作者決定。書稿、譯稿一律只標注、不逕改。

## 搭配

- 本 plugin 附一支 hook：Claude Code 每次 Write／Edit 寫入新內容後，自動掃簡體、一簡多繁、錯轉三類，有命中就提醒（不擋寫入）。路徑含 `zh-CN`、`zh_CN`、`zh-Hans`、`zh-SG`、`zh-MY`（不分大小寫，`-`、`_` 或不加都算）的簡體在地化檔會跳過；設環境變數 `ZHTW_GUARD_OFF=1` 可關閉。
- 寫對外文字時，接著用 `zh-tw-anti-slop` 去 AI 腔。
- Word 書稿（.docx）整本檢查改用 `manuscript-check`，它的簡體檢查與本 skill 共用同一份清單。

## 限制

- 一簡多繁、錯轉是手列清單，不是全集；掃不到不代表沒有。
- 用語判斷是詞級比對，不懂句意。B 級命中都要人判。
- 不處理「台／臺」「裡／裏」這類兩可的異體選擇，那是出版體例問題，照各出版社規定。
